# SP6b part 1: generated types, error contract, Monitor and Request details (on fixtures)

**Goal:** Move the console onto the wire types generated from Rust (`ui/src/gen`), give `DataSource` an abort and error contract, fix the Safari/Firefox "Apply (R)" focus drop, and build the Monitor and Request details screens on fixtures. There is still no live admin API; `FixtureSource` stays the only `DataSource`.

**Specs:** `docs/superpowers/specs/2026-10-25-console-design.md` → `docs/superpowers/design/console-ux-architecture.md` (§1.1 states, §5 Monitor, §6 Request details, §12 flows) → `docs/superpowers/design/console-design-system.md` (§1.4 syntax tokens, §4 query input, suggestion popover, score gauge, table row). Canvas boards `Monitor.dc.html` and `RequestDetails.dc.html` are illustration only.

**Constraints kept from SP6a:** strict CSP (no inline script or style, no static `style="…"`); styling only from `--vf-*` tokens; axe zero serious/critical in light and dark; initial JS ≤ 150 KB gz and each route chunk ≤ 80 KB gz; keyboard model and focus management like the existing screens; no new dependencies.

Branch `sp6b-console`, one commit per task, no push.

## Decisions

- **History and request shapes are provisional view types** (`HistoryRow`, `HistoryQuery`, `HistoryPage`, `RequestDetail`, `Bands`): SP4/SP5 own them and nothing in `ui/src/gen` covers them yet. The query DSL is the console's reading of UX §5; the server's parser (400 with a position) stays authoritative.
- **Range in the URL** is `range=15m|1h|24h|7d` (sliding with auto-refresh) or absolute `from&to`; custom from/to inputs are deferred.
- **Mutations** (ban, disable construct) need the admin API and the modal; part 1 shows them disabled with visible text.
