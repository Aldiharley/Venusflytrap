# Sub-project A (ATT&CK tags, measured confidence, event and group IDs, OCSF output): results

Sub-project A changes no detection. It adds fields to the judgment and to the audit line, and a second
output format: `serve --ocsf <path>` writes OCSF 1.9.0 JSONL beside the audit file. This file records the
acceptance run. Every number below was copied from the run output; nothing is estimated.

- **Baseline:** a build whose detection is identical to main `ed2a953` (`fix12b.exe`).
- **Measured tree:** branch `a-attack-ocsf` at `e704769`, release build.
- **Corpus:** the blazehttp corpus, with the dev/held-out split manifest (sha256 prefix `06d8905d897ba1a8`).
  Held-out was not touched.

## What changed (fields only)

- A judgment carries `attack` (a list of ATT&CK tactic and technique tags) and `confidence` (an integer
  0 to 100, or null), both derived from the deciding construct.
- Each audit line carries `event_id` (UUIDv7), `group_id` (a source and episode id shared by the
  requests of one chain episode), `confidence` and `attack`.
- `serve --ocsf <path>` writes one OCSF HTTP Activity (class 4002) record per request and one Detection
  Finding (class 2004) per Challenge or Block.

## Measured confidence

`confidence = floor(100 x lower bound of the Wilson 95 % interval of TP / (TP + FP))`, per deciding
construct (`top`), over the dev library run `a-dev.csv` (Challenge/Block rows only). Constructs that
decide fewer than 5 rows get no confidence (null). The table is generated by `eval/confidence.py` into
`crates/vft-core/src/confidence.rs`. TP and FP below were re-derived from `a-dev.csv` with the same
counting function.

| Construct | TP | FP | Confidence |
|---|---|---|---|
| `cmd.chained-command` | 9 | 0 | 70 |
| `path.directory-traversal` | 11 | 1 | 64 |
| `sqli.boolean-tautology` | 17 | 29 | 24 |
| `sqli.quote-breakout` | 12 | 5 | 46 |
| `sqli.stacked-query` | 3 | 3 | 18 |
| `sqli.union-select` | 15 | 40 | 17 |
| `xss.dangerous-proto` | 29 | 8 | 62 |
| `xss.event-handler` | 33 | 4 | 75 |
| `xss.script-tag` | 14 | 10 | 38 |
| `cmd.cmd-substitution` | 3 | 0 | none (3 rows) |
| `sig.etc-passwd` | 3 | 0 | none (3 rows) |
| `sig.schema-enum` | 1 | 0 | none (1 row) |

The low values are real and come from the corpus. For example, `sqli.union-select` is 17 because 40 of
its 55 deciding rows are benign: 25 of those are a benign `Referer` header
and 7 more come from the `bq` query parameter. `sqli.boolean-tautology` has the same
pattern (18 of its 29 false positives are `Referer`). A confidence of 17 therefore means "on this
corpus, this construct was right about a sixth of the time at the 95 % lower bound", not that the
construct is weak in general.

## OCSF smoke test

`venusflytrap serve --bind 127.0.0.1:18089 --upstream http://127.0.0.1:9 --audit a.jsonl --ocsf a.ocsf.jsonl --monitor-only`,
then three requests: a plain GET (`/index.html`), a query with a union-select construct
(`/search?q=1 union select username,password from users--`) and a configured decoy
(`/admin/backup.zip`). The upstream is closed, so each request got a 502 and the audit still recorded it.
The process was stopped afterwards and none was left running.

| Check | Result |
|---|---|
| Audit lines | 3, every one parses as JSON |
| Distinct `event_id` values | 3 of 3 |
| OCSF lines | 5, every one parses as JSON |
| HTTP Activity (class 4002) | 3 |
| Detection Finding (class 2004) | 2 (one per Block; the plain GET allowed) |

The union-select request was a Block with `confidence` 17 and ATT&CK T1190 in both the audit line and
the OCSF finding (`finding_info.attacks`, `confidence_score`). The decoy request was a Block (cause
`Ban`, reason "hard-block: request hit a honeypot decoy path") and its audit line and finding carry `attack: []` and `confidence`
null: when the proxy answers a decoy hit, the judgment's deciding construct is not
`honeypot.decoy-hit`, so the T1595.003 tag in the mapping above is not attached on this path. The
`honeypot.decoy-hit` tag is covered by a unit test on the judgment only.

## What this does not show

- Confidence is dev precision on one corpus (blazehttp), measured on rows that are partly artefacts of
  how the corpus was recorded (benign `Referer` headers). It is a measured number for this corpus, not a
  calibrated probability for another deployment.
- The mapping is by construct family, not per request: a request that decided on `xss.*` is tagged
  T1190 whether or not it is an exploit of a public-facing application.
- No SIEM was tested end to end. The OCSF records were checked against the 1.9.0 schema in the
  branch's tests (commit `e704769`); no ingestion pipeline consumed them.
- Held-out was not run: nothing in this sub-project can change a verdict, and the dev and serve diffs
  above are exact.
